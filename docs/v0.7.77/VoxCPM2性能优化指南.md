# 本地 VoxCPM2 语音速度优化指南

适用版本：奶绿 0.7.77，使用当前 Hermes profile 中 `voice/voxcpm2.json` 的 `"backend": "builtin"` 公共本地后端。若你使用的是 `legacy-profile` 或自定义语音脚本，应先检查那套实现，不要直接覆盖其配置。本指南说明现有实现和可调整项，没有承诺某种硬件的固定速度或加速倍率。

最值得先做的三件事：**检查是否一直在用 CPU、区分第一次加载与后续合成、保持设备不变后对比推理步数 10 和 8。**

## 先判断慢在哪里

| 现象 | 优先检查 |
| --- | --- |
| 文字回复本身很久才出现 | Hermes 使用的模型、工具与网络；这部分通常不是 VoxCPM2 |
| 第一次很慢，后续明显快 | 模型冷加载、设备初始化与磁盘读取 |
| 文字已经回来，每次仍要很久才有声音 | TTS 计算设备、模型环境、推理步数和资源占用 |
| 很快开始说，但中间经常停顿 | 持续生成速度是否跟得上播放、GPU／内存争用 |
| 重播旧消息很快，新消息很慢 | 旧消息可能直接读音频缓存，不能据此比较新合成速度 |

普通聊天与语音通话都要取得可用的最终回复，才合成应朗读的内容。语音通话还包含识别、Agent 回复、TTS 和播放缓冲，不能把整轮等待都算给语音模型。

## 0.7.77 已经采用的措施

- **常驻模型。** 同一 profile、同一配置下复用 Python worker 和已加载的模型；成功合成后不必每句重新加载。更改配置、切换 profile、退出应用或中途取消合成可能使 worker 重建。
- **通话准备时后台预热。** 开始语音通话时，TTS 模型准备与收音准备可以重叠。它不是每次启动 App 都加载模型，也不保证用户开口前加载已经完成。
- **短首段。** 首段最多 30 个字符，后续每段最多 150 个字符，并优先按标点或空白切分；同时受 `max_chars` 限制。
- **流式生成和播放。** 48 kHz 单声道 PCM 边生成、边传输、边保存，播放不必等待全文合成完成。它主要缩短开始听到声音的等待，不等于提高模型本身的计算速度。
- **复用已完成消息的音频。** 对已经完整保存的消息音频，重播直接读取缓存；新文字仍需合成。
- **减少额外处理。** 公共后端不加载降噪模型，合成时关闭额外文本规范化、降噪和坏例自动重试。参考录音需要本身清晰、干净。

口型能量与几何更新限制在约 30 Hz，避免在高刷新率屏幕上每帧重复更新；音频播放工作线程独立运行。

## 1. 确认模型实际使用的计算设备

公共配置模板的 `device` 是 `cpu`，这最兼容，但不代表速度最好。检查配置里指定的那个 Python 环境，而不是终端碰巧使用的另一个 Python。

| 环境 | 可尝试的 `device` | 前提 |
| --- | --- | --- |
| Apple Silicon Mac | `mps` | 该 Python 中的 PyTorch 能使用 MPS；实际速度需同机对比 |
| 有 NVIDIA GPU 的 Windows／Linux／WSL | `cuda` 或 `cuda:0` | 驱动、支持 CUDA 的 PyTorch 和显存均满足模型运行需要 |
| 无可用 GPU，或 GPU 环境不兼容 | `cpu` | 可运行，但较长回复可能慢于实时播放 |

AMD／Intel GPU 不等于支持 CUDA；本版公共后端没有 DirectML、ONNX 或 MLX 选项。WSL 中使用的是对应 Linux 环境，检查命令也应在同一发行版执行。

用 `voxcpm2.json` 中 `python` 字段的真实路径执行以下只读检查，路径按自己的环境替换：

macOS／Linux／WSL：

```sh
"/absolute/path/to/tts-venv/bin/python" -c 'import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.backends.mps.is_available())'
```

Windows PowerShell：

```powershell
& "C:\path\to\tts-venv\Scripts\python.exe" -c 'import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.backends.mps.is_available())'
```

输出依次为 PyTorch 版本、CUDA 是否可用、MPS 是否可用。对应设备显示 `True` 后，再在已有配置中只修改 `device` 并完成一次真实试听。可用性检查不等于模型已经成功运行，也不保证所有句子都比 CPU 快。报错时保留原配置和错误类别，先修正环境，不要同时更换模型和多个参数。

## 2. 分开测量冷启动和热合成

先备份自己的 `voice/voxcpm2.json`。在奶绿中选择本地 VoxCPM2，使用设置页试听做对比：App 重启或配置改变后，且模型尚未完成后台预热时，首次合成包含冷加载；保持应用、profile、配置不变，完成后再试听至少三次。设置页试听会新合成短句，比反复重播同一条历史消息更适合检查计算速度。

测量期间不要每次都重启 App，也不要在合成未结束时连续点停止／试听，否则可能反复重建 worker。修改配置后，将第一轮单独记录，并注明是否已经完成后台预热。

先关闭同机正在运行的大型 GPU 推理、绘图或视频生成任务，对比是否缓解显存／内存压力。模型放在本地 SSD 有助于加载，但不保证加快模型已经驻留之后的运算。长回复本身需要生成更多音频；希望交互更快时，可以让 Agent 先给简短回答。

## 3. 一次只调整一个参数

以下是公共后端的实际默认值与有效范围。保留现有路径、音频与其他字段，不要拿示例覆盖完整配置。

| 参数 | 默认与范围 | 调整建议 |
| --- | --- | --- |
| `inference_timesteps` | 默认 10；整数 1–100 | 先用 10 建立基线，再试 8。较少步数通常减少计算，但可能影响音质、发音和稳定性；以同机试听为准 |
| `cfg_value` | 默认 2.0；大于 0、不超过 10 | 速度对比时先保持 2.0，它不是主要提速开关 |
| `max_chars` | 默认 150；整数 1–1000 | 实际首段仍不超过 30、后续不超过 150；填 1000 不会变成千字单段。过小会增加分段开销，最多允许 48 段 |
| `request_timeout` | 默认 300 秒；大于 0、不超过 3600 | 只改变允许等待时间，不会让合成变快 |
| `seed` | 可省略；整数 0–4294967295 | 对照时保持同一值，便于比较；不是提速项 |
| `style` | 默认空；最多 500 字符，不含括号和控制字符 | 对照时保持相同、简短，不要同时改风格提示 |

例如，设备已经确认可用后，只把已有配置中的 `"inference_timesteps": 10` 改为 `8`，完成冷启动和三轮热合成，再比较声音。如果有漏字、失真或风格明显变化，恢复 10。

参考音频必须是有效 PCM WAV，最长 60 秒。60 秒是允许上限，并非推荐长度；使用清楚、自然、无冗余长静音的片段，缩短后要重新对比速度和音色相似度。模型目录必须是完整兼容的 VoxCPM2，包含正确的模型配置、`model.safetensors` 和 `audiovae.pth`；不要直接换成不兼容的旧版或量化文件。

## 4. 用现有时序记录定位等待

应用数据目录中的 `voice-latency.json` 保存最近 30 次记录，仅含时序、状态及数值，不保存回复正文或录音：

- macOS：`~/Library/Application Support/奶绿/voice-latency.json`
- Windows：`%APPDATA%\奶绿\voice-latency.json`

各条记录的 `ms` 对象是相对于该次操作起点的毫秒数，可比较：

| 差值 | 含义 |
| --- | --- |
| `ms.firstPCM - ms.ttsRequested` | 从请求 TTS 到首块音频到达 |
| `ms.playbackStarted - ms.ttsRequested` | 从请求 TTS 到播放引擎开始输出 |
| `ms.agentCompleted - ms.agentRequested` | Agent 这一阶段的等待 |

`playbackStarted` 来自播放引擎回调，不是扬声器声学测量，仍受输出设备延迟影响。某种操作没有相应字段时，就不计算该项；缺失不等于 0。失败、取消和缓存回放单独记录。`ttsCompleted` 与 `total` 可能包含流式传输的背压、缓冲或播放等待，不能作为纯模型推理耗时。

播放首缓冲约 1 秒，欠载后恢复缓冲约 0.8 秒；删减缓冲不会提升模型算力，反而可能更容易断续。诊断文件由应用尽力保存，缺少记录本身也不能证明合成没有发生。

建议记录设备／Python／PyTorch 版本、`device`、步数、一次冷启动和三次热合成的首音等待，并标记音质和断续情况。分享必要统计即可，不必上传完整 profile 或参考录音。

## 当前未启用的优化

本版公共后端使用 `optimize=False`，没有启用 `torch.compile`；也没有公开量化、dtype、批处理或线程数设置。应用封装未实现显式参考音频预编码缓存。不要把这些写成已经开启的加速功能，也不要直接向 JSON 加字段就认为它们生效。

语音进程使用受控环境变量列表，普通终端中设置的 `OMP_NUM_THREADS`、`MKL_NUM_THREADS`、`PYTORCH_MPS_*` 不会自动传给应用 worker。需要开发新的优化时，应在匹配源码中实现并单独测量，而不是给用户一个看似生效的启动参数。

Windows 仍为测试版，真实 CUDA／声卡及具体模型环境需在目标机器验证。相关安装与路径配置见 [用户接入说明](用户接入说明.md) 和 [Agent handoff](AGENT-HANDOFF.md)。

实现依据：`src/local-voice.mjs`、`native/voxcpm2-worker.py`、`src/main.mjs`、`src/voice-runtime.mjs`、`src/voice-timing.mjs`、`src/renderer/pcm-queue.mjs`；路径相对匹配版本的应用源码。
