# 奶绿 0.7.4 · 用户接入说明

本版可连接你自己的 Hermes 默认 profile 或命名 profile。奶绿是桌面界面，不附带 Hermes、模型、Python 环境、参考音频、API Key 或他人的人设与记忆。可以先独立试 Fish 朗读，再按需接入文字聊天和麦克风识别。

本版按当前已应用的七海 SVG 内容切换欢迎空状态：使用透明问号图，下方字标显示 **NANA7MI**；恢复默认奶绿时回到原欢迎图和 MILKY GREEN。选择 Nana7mi 配色本身不会触发此联动。用户名字、签名、头像、大标题与聊天身份保持独立。**Windows 宿主尚未实际运行验收。** 升级保留已有配置。

转交他人时，提供对应平台的应用包与 `MilkyGreen-0.7.4-handoff.zip`，请对方 agent 先读其中 `AGENT-HANDOFF.md`，从其现有环境接入；不要转交个人 profile 导出包。

## 1. 运行和已有设置

- Windows 10／11 x64：选择便携 EXE，或完整解压运行目录 ZIP 后启动其中的 `MilkyGreen.exe`；二者只运行一种，不能单独搬走目录版 EXE。系统下限见 [Electron 44 的官方平台要求](https://github.com/electron/electron/blob/v44.4.3/README.md#platform-support)。
- macOS 13 或更新版本：使用 Apple Silicon（arm64）应用包，本次未提供 Intel 包；最低系统版本来自所用 Electron 二进制的 Info.plist。文件名与校验记录见文末。
- 新安装默认地址为 `http://127.0.0.1:8642`，语音服务为 Fish，但没有预置密钥或 Voice ID。升级会保留已有连接地址、profile 目录和语音选项，不会强制切换到默认 profile。

Windows 测试包未附发行者代码签名；Mac 是 ad-hoc 本地签名、未公证。收到文件后先核对另附哈希，系统是否允许运行仍以目标机的实际结果为准。

应用设置与缓存仍存当前系统账户的应用数据目录；“便携 EXE”不代表退出后清除数据。Windows 通常为 `%APPDATA%\奶绿\`，macOS 通常为 `~/Library/Application Support/奶绿/`。不要把此目录、Hermes home 或个人语音模型打包发送给别人。

### 切换 Nana7mi 配色

点聊天面板右上角的调色盘按钮，选择 **Nana7mi**。这是第 5 套红黑灰浅色皮肤，选择后立即生效并自动保存，不需要再点设置页的保存按钮；保存成功后退出重开仍保持该配色。若保存失败，界面会提示并恢复之前的配色，可稍后重试。

配色只改变界面外观，不会自动选择或替换桌面立绘；要使用自己的 SVG，仍按下一节单独选择并应用。原有四套配色仍可随时切回。

## 2. 替换桌面立绘与原有轻摇

### 七海 SVG 的欢迎图联动

当前已应用的是本版识别到的七海 SVG 时，空聊天页显示方框问号欢迎图与 **NANA7MI** 字标；仅选择或取消尚未应用的文件不会改变欢迎区。识别依据 SVG 内容，不依赖文件名或界面配色，所以只重命名文件仍可识别；不同内容即使取同样文件名也不会触发。编辑过 SVG 内容的文件不保证匹配。切回默认奶绿会恢复原欢迎图、圆形装饰和 **MILKY GREEN**。

这一联动只改欢迎图片及其下方字标，沿用原字标字体、字号和字距。不会修改用户名字、签名、头像、大标题、聊天身份或配色；Nana7mi 配色仍可独立切换，其他 SVG 继续使用原欢迎图。欢迎图等待当前状态和图片就绪后显示，避免启动时闪过旧图。

问号 PNG 由提供的图像通过 imagegen 去底生成，存在轻微边缘和颜色差异，不是逐像素无损抠图。公开应用包含这张透明 PNG，但不含个人七海 SVG；需要使用联动时，在自己的机器上选择已有且有权使用的 SVG。原输入图与 SVG 不会被此操作改写。

### 选择、应用与轻摇

打开聊天面板的“设置”，在“表情与动效”下方找到“桌面立绘”。这里显示当前立绘的文件名和操作按钮，不再展示图片预览或重复的文件名。

点“选择 SVG”，选择本机不超过 16 MiB 的 `.svg` 文件。应用会在内部检查文件，状态文字会说明是否就绪、是否识别到轻摇；选择后桌面立绘仍不改变。检查完成后点“应用立绘”才生效。“取消选择”会放弃尚未应用的文件；“恢复默认奶绿”回到内置角色。选择无效、文件无法解码或取消操作时，当前立绘保持不变；正在聊天或播放语音时，先等当前活动结束再应用或恢复。

导入保留透明背景与比例，并按可见内容去掉底部透明余量，使可见底沿对齐立绘窗口的底边。在工作区底边附近放置时，自定义 SVG 会自动贴合底边，避免旧位置留下细缝；放到其他位置仍可自由摆放。应用保存自己的副本，成功应用后移动或重命名原文件不会使已选立绘丢失；原 SVG 不会被改写，也不会加入默认资产或公共安装包。不需要从另一会话分享、导出或重新制作角色文件，直接选择已保存在本机的文件即可。

如果识别到支持的原有轻摇，应用后可在“表情与动效”→“动作”中使用“轻摇”和“动作幅度”。幅度范围为 0%–160%；关闭轻摇或调到 0% 会保持静止。这里只开放检测到的轻摇：表情、状态和其他动作仍不可用。没有识别到受支持动画时，立绘照常静态显示，不会自动添加摇动。

本版只接入单个外层图形组的简单 CSS 平移加旋转循环，并不执行 SVG 脚本或任意动画。支持时保留原循环时长、缓动、水平位移和旋转节奏；为让截断底沿贴住窗口底边，垂直位移会改用底边补偿，因此不保证逐像素复刻原网页动画。已有暂停、叠加变换或超出支持范围的动画会保留为静态立绘。

自定义 SVG 不自动获得眨眼、表情、口型或完整角色绑定。Fish／本地 TTS 仍独立播放声音；听得到声音但嘴不动是预期行为。名字、聊天头像、桌面立绘和 Hermes agent 的身份／人设彼此独立，不随 SVG 文件名自动改变。恢复默认奶绿后可继续使用内置角色原有表现。

依赖外部图片／字体、脚本或网页内容的 SVG 可能无法导入；可回原工具导出自包含 SVG 后重试。文件检查失败、全透明或报错时保留当前立绘。不要为识别轻摇而启用角色脚本或转交整个个人应用数据目录。

最短检查：选择→检查就绪→取消选择，确认旧立绘不变；再次选择→应用，确认透明处不阻挡桌面、人物处可拖动；若支持轻摇，检查开关、幅度和摇动时的点击位置；退出重开仍显示所选立绘；恢复默认正常。Dock 贴合还需在实际系统中确认，不能仅凭文件检查成功判断。

## 3. Fish Audio：不依赖 Hermes 或 ASR 的第一步

进入设置的“声音与陪伴”，选 **Fish Audio 在线**，填自己的 API Key 和有权使用的 Voice ID，选择模型，再点“保存并试听”。Voice ID 必须是 32 位小写十六进制 ID，不是完整网页地址。模型选项是 `s2.1-pro-free` 和 `s2.1-pro`；后者是按量计费选项，账户额度以 Fish 为准。程序使用所选模型，不自动切换音色或付费模型。[Fish 官方 TTS 参数](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech)

Fish 只合成语音。试听文字、随后朗读的回复文字会发送到 Fish；麦克风识别另外使用本地 ASR。Key 通过应用界面输入，并由当前系统账户的加密能力保存，不写入这些模板。换电脑或系统账户后应重新输入。Hermes 的 `API_SERVER_KEY` 是另一种凭据，不能填进 Fish 字段。

验收：短试听能出声，停止按钮能及时结束，再次试听可用；内置默认角色可另检查口型，自定义 SVG 立绘没有口型。401 先检查 Fish Key，402 检查账户权限／额度，429 稍后重试或检查限额；不要靠切换付费模型掩盖错误。仅测试 Fish 不用先安装 Hermes、Python 或 ASR。

## 4. 先确定地址、profile 与认证目录

确认现有 Hermes 自身能正常对话；记录你要连接的 profile ID。中文显示名可以任意，profile ID 则使用 Hermes 的规范名称：1–64 位，首位为小写字母或数字，其余可用小写字母、数字、`_`、`-`。`default` 对应根 Hermes home，不是 `profiles/default`。[官方 Profiles 指南](https://hermes-agent.nousresearch.com/docs/user-guide/profiles)

在“Agent 连接”同时设置地址与配置文件夹，二者必须指向同一个 agent：

| 实际网关方式 | 本地 Agent 地址示例 | 应选择的配置文件夹／认证来源 |
| --- | --- | --- |
| 默认 profile 的监听器 | `http://127.0.0.1:8642` | 根 Hermes home |
| 命名 profile 的既有独立监听器 | `http://127.0.0.1:9001` | `HERMES_ROOT/profiles/research` |
| 共享网关服务命名 profile | `http://127.0.0.1:8642/p/research` | `HERMES_ROOT/profiles/research` |
| 共享网关的默认路由 | `http://127.0.0.1:8642/p/default` | 根 Hermes home |

端口是例子，应沿用实际监听端口。地址是 API 根地址，**不加 `/v1`、`/v1/chat/completions` 或网页 dashboard 路径**。本版只接受本机 HTTP 回环地址和可选 `/p/<profile>` 前缀；不支持远程 IP、URL 内密码、查询参数或片段。

留空配置文件夹时，应用按地址里的 profile 推导本机默认目录；无前缀地址推导根 home。因此独立端口上的命名 profile、WSL、自定义数据目录必须明确选择其实际文件夹。应用只能看到自身启动环境中的 `HERMES_HOME`，不能依靠另一个终端临时设置的变量。

| 环境 | 根 Hermes home 示例 | 命名 profile 示例 |
| --- | --- | --- |
| macOS | `~/.hermes` | `~/.hermes/profiles/research` |
| Windows 原生 | `%LOCALAPPDATA%\hermes` | 上述目录下的 `profiles\research` |
| Windows 旧目录 | `%USERPROFILE%\.hermes` | 上述目录下的 `profiles\research` |
| Windows 应用连接 WSL | `wslpath -w "$HOME/.hermes"` 输出的 UNC 路径 | 上述目录下的 `profiles\research` |

表中 `~` 和环境变量只用于定位目录；用文件夹选择器选择后，路径字段应显示完整实际路径，不填 `%LOCALAPPDATA%`、`~` 或模板占位文字；也不要选 Hermes 代码仓库、虚拟环境或模型目录。Windows 原生和 WSL 可以共存，选择已有环境即可。[Windows 原生目录](https://hermes-agent.nousresearch.com/docs/user-guide/windows-native)、[WSL2 指南](https://hermes-agent.nousresearch.com/docs/user-guide/windows-wsl-quickstart)

奶绿先从**所选目录**的 `.env` 读 `API_SERVER_KEY`；没有该项时，支持该目录 `config.yaml` 中的 `gateway.api_server.key`、`gateway.platforms.api_server.key` 或 `platforms.api_server.key`。重复／冲突值会报错，不会向父 profile 借用密钥。已有有效配置不用改写为 `.env`。共享命名路由必须使用目标 profile 自己的 Key，不能复用根默认 profile 的 Key。[Hermes API 认证](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server#authentication)

## 5. 可选 API 配置工具

已有 API 可用，直接跳到下一节。另附 `tools/setup-hermes-api.py` 只帮助**已有 profile**补齐缺少的回环监听变量或 Key；需要 Python 3.8+ 标准库，不安装依赖、不创建 profile、不修改模型／人设／工具权限，不改 `multiplex_profiles` 或 `standalone`，也不启停网关。

先选择与现有网关一致的方式，运行预览。确认输出目录和端口符合预期后，在**同一命令末尾**加 `--apply` 才写入。`--hermes-home` 总是根 Hermes 数据目录，`--profile` 是规范 ID。下面命令从交付目录运行：

```bash
# macOS 或 WSL：默认 profile，根监听器
python3 tools/setup-hermes-api.py --hermes-home "$HOME/.hermes" --profile default --mode direct

# 已有独立网关上的 research：只处理该 profile，端口按实际情况调整
python3 tools/setup-hermes-api.py --hermes-home "$HOME/.hermes" --profile research --mode direct --port 9001

# 已有共享网关：处理默认监听配置和 research 自己的认证 Key
python3 tools/setup-hermes-api.py --hermes-home "$HOME/.hermes" --profile research --mode shared --port 8642
```

Windows 原生在 PowerShell 中运行相同工具，例如：

```powershell
py .\tools\setup-hermes-api.py --hermes-home "$env:LOCALAPPDATA\hermes" --profile default --mode direct
```

WSL Hermes 的工具应在 WSL 终端运行，传 Linux 路径；不要让 Windows Python 通过 UNC 改写 Linux 配置。`--mode direct` 是默认值。`--port` 省略时保留已有端口；没有已有端口的默认／共享监听器采用 8642，新的独立命名 profile 要显式提供端口。

工具要求每个待处理 profile 已有 `config.yaml`，不会把空目录当成安装完成的 agent。工具不会覆盖已有 Key 或冲突端口；写入前检查全部涉及文件，旧 `.env` 留同目录 `.env.before-milky-*` 备份。保留原注释、换行与无关字段；普通写入失败会尽力回滚已写文件；若同时有人修改配置，会保留并发修改并报告人工核对。POSIX 新文件仅当前用户可读写，Windows 使用目录继承的 ACL。不要同时让其他工具改同一配置。

发现既有 YAML API 设置、含歧义的 `.env` 语法、链接／重解析目录或失效 profile 时，工具会停止，保留原状。工具的保守检查比应用读取更严格；这种情况按现有 Hermes 配置人工核对即可，不要删旧 Key 强行重跑。工具没有联网验证，也没有保证网关已经启动。

独立监听器继续按其现有服务方式运行。共享网关必须实际服务目标 profile；用 `hermes -p default gateway status` 检查，命名 profile 不得处于已暂停／独立服务状态。**无需为了奶绿把可用的独立网关迁移成共享模式。** 只有选共享路由时才依赖 `gateway.multiplex_profiles`；现代 Hermes 默认会做启动预检，具体迁移和冲突按 [官方共享网关指南](https://hermes-agent.nousresearch.com/docs/user-guide/multi-profile-gateways)处理，不复制一个强制开关覆盖现有拓扑。需要重载配置时，由现有网关所属环境按其服务方式重启原实例。确无既有网关、且准备启动默认 profile 时，可按当前 Hermes 的帮助在前台运行 `hermes -p default gateway`；保持终端运行，再测试连接。不要同时执行前台启动和已有后台服务启动。

## 6. 文字连接与 WSL 检查

点击“保存并测试连接”。应用要求 Hermes 的 `/v1/capabilities` 声明 `platform: hermes-agent`、`run_status` 和 `run_events_sse`；实际聊天还使用 `/api/sessions`、`/v1/runs`、任务事件与停止接口。普通 OpenAI 兼容聊天端点不能代替这些接口。[Hermes capabilities 和 Runs API](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server#runs-api-streaming-friendly-alternative)

连接成功后发一条简短文字，确认完整回复，再开始新会话并重开应用检查会话行为。更换地址或 profile 后会重建后端会话；面板已有显示记录保留，新 profile 从新的后端会话开始。角色名字来自该 profile 的显示元数据，不替换其真实人设；模型与思考强度沿用 Hermes 当前设置。连通检测通过但运行报错时，应检查所选 Hermes 的模型、工具与网关状态，不要复制其他 profile 的配置。

Windows 连接 WSL 时：PowerShell 用 `wsl --list --verbose` 查看发行版；对应 WSL 终端用 `wslpath -w "$HOME/.hermes"` 或目标 profile 路径取得 UNC 写法。Windows 到 WSL 通常可用回环地址；若失败，先确认发行版和网关运行，再检查 localhost 转发。[Microsoft WSL 网络说明](https://learn.microsoft.com/en-us/windows/wsl/networking)

`Test-NetConnection 127.0.0.1 -Port 8642` 只验证端口，不验证 Key 或 API 能力。不要把 WSL 的 `172.x` 地址填入本版。WSL 本地语音桥接还依赖默认 `/mnt/c` 等自动挂载；关闭自动挂载或自定义 mount root 时要先调整环境。[WSL automount 设置](https://learn.microsoft.com/en-us/windows/wsl/wsl-config#automount-settings)

## 7. 可选本地朗读与麦克风识别

本地模型与 Python 环境由你准备。模板位于 `templates/voice/`，只复制需要的配置到**所选 profile**的 `voice/` 目录；默认 profile 则使用根 home 下的 `voice/`。先替换所有路径，再保存为对应正式文件名。不要覆盖已有可用语音配置。

**VoxCPM2：** `voxcpm2.example.json` 对应 `voice/voxcpm2.json`，`backend: "builtin"` 使用应用内附 worker。需要你自己的 Python、完整本地 VoxCPM2 模型目录和有权使用的 60 秒以内 PCM WAV（单／双声道）参考音频；模型与音频不随包。字段为 `python`、`model_dir`、`reference`、`device`，以及分段上限和推理选项。新公共后端不依赖个人 profile 脚本或控制提示文件。

**ASR：** 选择一个模板保存为 `voice/asr.json`。SenseVoice 为 `provider: "sensevoice"`；Nano 为 `provider: "fun-asr-nano"`，必须是 **Fun-ASR-Nano-2512-hf 的 Transformers 格式检查点**，不是同名的原始格式。路径字段是 `modelPath`，与 TTS 的 `model_dir` 不同。ASR 是麦克风功能所需，文字聊天和 Fish 试听不依赖它。

先用 `device: "cpu"`。TTS 可按实际 PyTorch 支持改为 `cuda`／`cuda:N`，macOS 才可用 `mps`；ASR SenseVoice 使用 CPU，Nano 可用 CPU 或 macOS MPS。Windows JSON 路径中的反斜杠写成 `\\`；WSL 配置中的 Python、模型和参考音频用 Linux 绝对路径，应用的 profile 字段则用 Windows UNC 路径。

麦克风对话还要求 Hermes 已连接、自动播放回复语音已开启、安静模式已关闭，系统允许桌面应用使用麦克风。先验证 ASR 识别，再验证一轮识别→回复→朗读与停止。依赖安装、模型准备和离线预检细节见 `AGENT-HANDOFF.md`。

## 8. 常见失败与最短验收

| 现象 | 先检查 |
| --- | --- |
| 连接超时／拒绝 | 环境、实际端口、原网关是否运行；WSL 再查回环转发 |
| Hermes 401 | 地址所服务的 profile 与所选认证目录是否一致，Key 是否有效；不要用根 Key 代替命名 Key |
| 404 | API 地址是否多加 `/v1`；共享前缀名称和 served profiles 是否正确；独立监听器使用根 URL |
| 服务不支持任务接口 | 是否接错服务／过旧 Hermes；以实际 capabilities 为准，不改成通用 chat completions |
| helper 拒绝修改 | 看预检类别，保留旧文件；YAML／端口／重复 Key 冲突由接手 agent 就地核对 |
| Fish 无声 | 系统输出设备与应用音量、Key／Voice ID／模型权限、网络；不需要先装 ASR |
| SVG 文件检查失败 | 文件是否为自包含 SVG、是否依赖外部资源；保留当前立绘并回原工具重新导出 |
| 自定义 SVG 不摇／动作不可用 | 是否识别到受支持轻摇、轻摇开关和幅度是否开启；未识别时静态显示属于预期 |
| 自定义立绘听得到但嘴不动 | 自定义 SVG 不绑定口型，无需为此重装语音环境 |
| 本地语音不可用 | 当前 profile 的 JSON 路径、对应 Python 依赖和模型格式、设备支持、WSL 挂载 |

最短验收：启动与托盘→调色盘切换 Nana7mi、确认保存并在重启后保持→可选 SVG 选择／检查／取消／应用／轻摇／恢复默认→独立 Fish 试听／停止→保存并测试连接→一轮文字与新会话→可选本地语音→退出重开。Windows 还需测跨应用鼠标移动／点击／滚轮、键盘不算鼠标活动、混合 DPI 多屏贴靠，以及退出后活动组件结束。记录失败步骤、系统版本、错误类别；不发送 Key、`.env`、参考音频或完整聊天记录。
